# 串口命令与接收解析

发送区选择「命令」，在「管理命令与接收规则」（Windows 为「协议规则」）创建规则。
保存只修改配置，不发送数据。预览和试算无需连接设备。

两端编辑器的「帧配置」提供常用片段，可拖入帧模板输入框或点击插入。
包括帧头 AA BB、u8/u16be/u16le/i16be/u32be 参数以及 SUM8/XOR8/CRC16-Modbus 校验。
帧头插入开头，参数插入校验前并自动避开重复字段名；选择校验片段会替换已有校验。
已有帧数据保留，不创建新规则。插入后仍可直接编辑字段名称、范围和帧头，保存后生效。

## 电机速度示例

以下帧头、范围及校验是假设，使用前请替换为设备真实协议。

```json
[
  {
    "name": "motor-speed",
    "template": "AA BB {speed:u16be:0:3000} {checksum:sum8}",
    "response": "motor-speed-report",
    "timeout_ms": 1000
  },
  {
    "name": "motor-speed-report",
    "receive": true,
    "template": "CC DD {speed:u16be} {checksum:sum8}",
    "display": "电机速度：{speed} rpm"
  }
]
```

导入后输入 `motor-speed 45`，预览为 `AA BB 00 2D 92`。Enter 发送；上下键切换历史。
macOS 显示可选 alias；Windows 使用 Tab 补全唯一匹配的 alias。
收到 `CC DD 00 2D D6` 后显示 `电机速度：45 rpm`。

## 模板

- 固定字节：两位 HEX，使用空格分开。
- 参数：`{名称:类型}`，可加上下限，如 `{speed:u16be:0:3000}`。
- 类型：`u8/i8`，`u16be/u16le/i16be/i16le/u32be/u32le/i32be/i32le`。
- 调用参数按模板出现顺序填写，支持十进制、`0x` 十六进制和负数。
- 校验位只能位于帧尾：`{checksum:sum8}`、`{checksum:xor8}`、`{checksum:crc16modbus}`。
- 校验范围从 0 开始，起点包含、终点不含；终点为空表示校验前的全部剩余数据。
- CRC16-Modbus 使用初值 FFFF、多项式 A001，低字节先发送。
- 显示模板可引用参数，如 `速度：{speed} rpm`。
- 命令模式不叠加普通发送的编码、校验和行尾，不支持自动发送。

二进制接收规则必须以固定字节开始，帧长度由模板自动确定。
文本接收规则将 `template` 设为空、`delimiter` 设为 HEX（例如 `0D 0A`），
`display` 使用 `{text}`；文本按 UTF-8 解码，不包含分隔符。

## 接收与边界

半帧等待后续数据，多帧逐帧解析。完整且通过校验的帧优先于其他规则的未完成帧；仅通过校验和字段验证的多个候选会报告冲突。校验失败、字段越界、规则冲突和未匹配数据会明确标记；
失败记录不作为有效反馈。原始收发内容始终保留在终端。
接收显示可切换原始、解析、同时；解析记录最多 2000 条，单帧最多 4096 字节。
断开连接、更换规则或显示缓冲丢失时清空拼帧缓冲。
配置最多 128 条，名称必须唯一；不执行任意脚本。

可关联接收规则并设置超时，但匹配只表示发送后收到了该类反馈，未验证请求序号，
不能据此认定设备执行成功。连续发送会替换当前等待的反馈。

配置存储于本地，两平台共用 JSON 数组格式。导入替换编辑列表，保存后生效。
macOS 可导入导出 JSON 文件；Windows 编辑器支持 JSON 文本导入导出。
不支持长度字段决定帧长、循环脚本和自动单位换算。
